# Approval Gate

人間承認が必要なケースを判定するテンプレート。
**判定に迷う場合は `yes`（承認必要）に倒す**（安全側デフォルト）。

## 判定観点（1 つでも該当すれば yes）

| #   | 観点                 | 例                                                   |
| --- | -------------------- | ---------------------------------------------------- |
| 0   | **Hardening Override（HO）対象パス接触** | `.claude/rules/*.md`・`.claude/settings*.json`・`.claude/commands/*.md`・`.claude/agents/*.md`・`scripts/hooks/*.sh`・`bin/plangate`・`schemas/*.schema.json`・`.github/workflows/*`・`AGENTS.md`/`CLAUDE.md`（正本: `mode-classification.md` の HO 9 カテゴリ）。**該当なら他観点にかかわらず無条件 yes + 最低 high** |
| 1   | データ削除           | レコード削除・ファイル削除・履歴の破棄               |
| 2   | DB schema 変更       | migration・カラム削除・型変更                        |
| 3   | 認証・認可変更       | 権限モデル・ロール・トークン・セッション             |
| 4   | 課金・請求変更       | 料金計算・プラン・決済連携                           |
| 5   | 外部 API 変更        | 公開 API の破壊的変更・外部サービス契約に影響        |
| 6   | 本番設定変更         | 環境変数・インフラ・シークレット                     |
| 7   | CI/CD 変更           | workflow・デプロイパイプライン・ブランチ保護         |
| 8   | 大規模リファクタ     | 多数ファイル横断・アーキテクチャ変更                 |
| 9   | 依存関係追加         | 新規ライブラリ・メジャーバージョン更新               |
| 10  | セキュリティ設定変更 | CORS・CSP・暗号化・監査設定                          |
| 11  | irreversible な変更  | force-push・履歴書き換え・tag/release 発行・外部公開 |
| 12  | プロダクト判断が必要な UI/UX 変更 | デザイン方針・UX フロー・ブランド一貫性など、技術妥当性だけでは決められない変更 |

補足判定:

- 上記に「間接的に到達する」変更（例: 設定生成スクリプトの変更が本番設定に波及）も該当扱い。
- 自動化・学習ループが**自分の承認条件・ゲート自体を変更する**提案は、内容にかかわらず yes。

```markdown
# Approval Gate — <TASK-ID / 変更名>

## Requires Human Approval

yes / no

## Reason

<該当した観点番号と、具体的にどの操作が該当するか。no の場合は
「全 12 観点に非該当」の確認結果>

## Risk Level

low / medium / high / critical

<根拠: 影響範囲 × 可逆性 × 検知可能性。判定に迷う場合は
`mode-classification.md` の定量基準（変更ファイル数・受入基準数・影響レイヤー）で
裏取りし、判定不能は 1 段階上へ倒す>

## Safe Alternative

<承認なしで進められる安全な代替案。例: 削除→アーカイブ移動、
直接変更→変更スクリプトの提示（dry-run つき）、一括→段階適用。
代替がなければ「なし（承認必須）」>

## Approval Request

<人間に提示する承認依頼文。以下を含む:

- 何を・なぜ変更するか（1〜2 行）
- 実行される具体操作（コマンド・対象）
- 失敗/事故時の巻き戻し手順
- 承認しない場合の影響>
```

## 運用ルール

- `yes` の場合、承認取得まで**実行しない**（計画・差分準備・dry-run までは可）。
- 承認は操作単位。1 つの承認を別の操作に流用しない（スコープ超過は再承認）。
- 承認の記録（誰が・いつ・何を）を作業コンテキストに残す。
- **AI は人間承認の記録（承認トークン・approval ファイル）を代理作成しない**。
  口頭指示があっても、承認記録の発行は人間の操作として実施してもらう。
