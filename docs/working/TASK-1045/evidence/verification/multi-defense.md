# A-11: 併記回避の多重防御を再実測（plan Step 6 / AC-07 / T1045-TC-07）

- 実行日: 2026-08-13 / 修正後 guard（`feat/1045-exec`）
- 起票時実測は根拠にせず、本 PBI 内で `PreToolUse` payload により再実測した。

`/dev/null` 破棄を除外対象に加えたことで
「`ls > /dev/null ;` を前置すれば `>` 判定を回避できる」形が生まれうるが、
`copy-like` ルールが独立に捕捉するため回避は成立しない。

| # | コマンド | rc | 捕捉ルール |
|---|---|---:|---|
| (1) | `ls > /dev/null ; cp <TOKEN> /tmp/x` | **2** | `copy-like`（`>` は正規化で消えるが `cp` が残る） |
| (2) | `cp <TOKEN> /tmp/x` 単独 | **2** | `copy-like`（`>` を含まない） |
| (3) | `printf x \| tee <TOKEN>` 単独 | **2** | `copy-like`（`>` を含まない） |
| (4) | `mv /tmp/x <TOKEN>` 単独 | **2** | `copy-like`（`>` を含まない） |

**4 形すべて exit 2。`SC-6` は発火せず。**

(2)(3)(4) が `>` を 1 文字も含まないまま block されることは、
「`>` 判定は多重防御の 1 本にすぎず、除外を入れても他ルールが独立に機能する」
ことの直接証拠である。

スイート上の機械担保: `T1045-TC-07`（通常群、上記 4 形をループ assert）。
