## サマリ

v8.16.0 の目玉は、次世代ワークフロー「ai-loop」（旧 Arbiter）を ai-loop 自身の
開発プロセスへ自己適用する **dogfooding として初の実運用サイクルを完走**した
ことである。Run-001〜021 を通じて摩擦（friction）検出 → W チェック（3R 合議）
→ 仕様への正本化を反復するセルフチューニング閉ループ（F-1〜F-41）を確立した。
**PlanGate 本番フロー（WF-00〜07、通常の plan → C-3 → exec ゲート運用）への
ai-loop 適用は未実施であり、本リリースはあくまで低リスク帯における PoC（概念
実証）である。** `ai-loop-cycle` スキルは plangate プラグインへ同梱され、他
プロジェクトでの低リスク帯検証に利用できる。

あわせて Hook Enforcement の物理配線を 6/12 → 11/12 に前進させ、サブエージェ
ント委譲プロトコル正本・doctor 検査の追加・段階的導入ドキュメント・新規スキル
（`ai-loop-cycle` / `pr-watch`）などを追加した。品質コマンド証跡必須化など
5 件の仕様は v8.15.0 からの状態変化がない（仕様 + apply-script 提供までで、
実適用は次リリース以降に持ち越し）。個々の変更点・PR 番号は CHANGELOG を参照。

## ハイライト

- **ai-loop dogfooding 初回実運用サイクル完走（Run-001〜021）** —
  `HUMAN_ESCALATED → 人間判断 → AUTO_APPROVED` のフル経路を完走した後、摩擦
  検出→合議→正本化を反復するセルフチューニング閉ループを確立。auto-merge を
  廃止し merge-ready 運用に一本化した（**本リポジトリの ai-loop 関連 PR の
  内部マージ運用のみ・外部利用者のフローに影響なし**）ほか、rubric grader
  再試行ループ・摩擦 ID 台帳の単一権威化などのプロセス改善を含む。
  **対象は低リスク帯変更に限定した PoC であり、PlanGate 本番フロー
  （WF-00〜07）を置き換えるものではない。**
- **ai-loop-workflow を plangate プラグインへ同梱** — `ai-loop-cycle` スキル
  を Agent Skills bundled resources 方式で自己完結配布し、他プロジェクトでの
  低リスク帯検証を可能にした。
  **利用前に、スキル同梱の
  [`ho-paths.md`](https://github.com/s977043/plangate/blob/main/plugin/plangate/skills/ai-loop-cycle/references/ho-paths.md)
  （雛形）を自プロジェクトの Hardening Override 対象パスで確定すること。**
  未確定のままだと arbiter は安全側に倒れ、全件が human escalate になる。
- **サブエージェント委譲プロトコル正本** — 複数エージェントへ作業委譲する際
  の責務分界・引き継ぎ形式・検証手順を正本化。
- **doctor 検査 3 件追加** — W-6 暫定記録検知・skill 名多重定義検知・
  pre-push ガード配線検知。
- **Hook Enforcement 物理配線 6/12 → 11/12** — CLI 層 5 件（EH-4 / EH-5 /
  EHS-1 / EHS-2 / EHS-3）を `bin/plangate` / `scripts/hooks/*.sh` /
  `schemas/*.schema.json` へ実適用。実装は 12/12・物理配線は 11/12（残る
  EH-7 は GitHub branch protection 依存で doctor 可視化のみ）。
- **ai-loop（旧 Arbiter）仕様策定 + L2 裁定エンジン PoC** — コンセプト固定 →
  decision table → lite 判定基準 → 裁定エンジン PoC（59 テスト）→ C-3 を
  AI 裁定ゲート「C-3'」へ置換する概念改定、まで一連の仕様策定を実施。
  **本番運用切り替え・既存 plan → exec フローの置換は未実施**（PoC・仕様段階）。
- **Plan Review Readiness Gate** — C-1 self-review 前に
  `pass / needs_revision / blocked` を判定する計画実行準備ゲートを新設。
- **exploratory intent（8 分類化）+ hypothesis-logger** — intent-classifier
  に `exploratory` を追加し、仮説採番・記録スキルを新設。
- **段階的導入ドキュメント 3 種** — plugin-only 環境の動作境界、既存
  plan → exec ワークフローとの共存ガイド、改称移行チェックリストを新設。
- **repo-owned 整合性検出スクリプト 2 種** — stale パス参照検出・
  plugin/repo-local スキル名多重定義検出。前者が実際に検出した既存ドキュメント
  の壊れたリンク 3 件を dogfooding で修正済み。
- **gh account ドリフト検証の pre-push opt-in 拡張**。
- **新規スキル・スキル拡張** — `ai-loop-cycle` / `pr-watch` を新設、
  `subagent-driven-development`（worktree 委託安全ルール）・`self-review`
  （シェル/ドキュメント/文章品質観点）を拡張。

## リリース手順（Human-owned・参考）

tag push / GitHub Release 発行は
[`.claude/rules/responsibility-classes.md`](https://github.com/s977043/plangate/blob/main/.claude/rules/responsibility-classes.md)
「対外公開アーティファクト publish 責務分界」により **Human-owned**（または
計画段階で明示承認を取得した AI 実行）。本ファイルは AI が作成した release
note 確定版であり、`git tag` push・`gh release create` の実行は行わない。

1. 本ノートの内容を人間がレビューし、バージョン番号 v8.16.0 を確定する
   （CHANGELOG.md は `## v8.16.0 (2026-07-08)` 見出しへ確定済み）。
2. 対象ブランチ（`release/v8.16.0-prep` またはそのマージ後の `main`）の
   確定 SHA を確認する。
3. `git tag v8.16.0 <確定 SHA>` → `git push origin v8.16.0`。
4. [`scripts/check-tag-main-parity.sh`](https://github.com/s977043/plangate/blob/main/scripts/check-tag-main-parity.sh)
   で tag が指す commit と `origin/main` の一致を検証（NO RELEASE WITHOUT
   TAG-MAIN PARITY）。
5. `gh release create v8.16.0 --notes-file <確定 note>` で GitHub Release を発行。
