## 指摘 2 への設計（本 v4 の中核）

### 検査不能時の verdict

**一般則（plan §3-quater）**: **免除（`unmigrated` / `pending(defer)`）の根拠となる検査が
実行できない場合、免除を与えず `undecidable`（NG）へ倒す。**

| 検査 | 実行不能の例 | verdict | TC | MUT |
|------|------------|---------|----|-----|
| issue state（OPEN/CLOSED） | ネットワーク不通 / `gh` 不在 / 未認証 / rate limit / timeout / 解釈不能な応答 | **`undecidable`** | TC-29, TC-30, E-13 | **MUT-10** |
| 凍結リスト読み取り（F-1） | ファイル不在 / 破損 / ヘッダ SHA 欠落 | **`undecidable`** | TC-31, E-14 | **MUT-11** |
| 凍結ベースライン取得（F-2） | shallow clone / tarball / 凍結コミットが履歴に無い / 非 git | **`undecidable`** | TC-32 | **MUT-12** |
| （静的確認） | 「取得失敗→OPEN とみなす」「取得失敗→制約なし」分岐の**不在** | — | **TC-33** | — |

**運用コストを隠していない**: offline / shallow clone では免除行が全 NG ＝ `--check` は NOT READY。
解消は **(a) 到達可能な full checkout で実行** か **(b) 免除を解消**の 2 つで、
**「検査を諦めて緑にする」経路を作らない**と明記した。

### 凍結集合の materialize（同語反復の回避）

**`scripts/apply-contract-freeze.list`（台帳とは別ファイル）**を正本に置く。

- **F-1**: `contract=legacy` 行 ⊆ 凍結リスト。**台帳だけを編集しても `legacy` は増やせない**
  → **TC-27 が非空振りになる**（v3 は許可集合の出所が未定義で、台帳の `legacy` 行から導く実装なら空振りだった）
- **F-2**: 凍結リスト ⊆ **ヘッダに記録した凍結コミットの blob**（**固定した 1 点**。「直前のコミット」ではないので drift しない）
  → `adopted → legacy` の差し戻しは**凍結リストへの再追加＝拡大**なので F-2 が FAIL させる（＝「一方向」の前状態取得元を固定した）
- **MUT-13** が「台帳の `legacy` 行から凍結集合を導く」逆戻り変異を kill

**残る限界を明記**: 凍結リスト・台帳・ヘッダ SHA を**整合的に**書き換えれば通せる。
これは **R-004 と同一の穴**で本 PBI では塞げない（follow-up / T-21）。
保証するのは **同語反復でない / 単一ファイルの編集では広がらない / 黙って広がらない**の 3 点であり、
**改竄不能ではない**と plan に書いた。

### AC-5 との衝突を「単調安全性」で解消

検査不能を NG に倒す以上 verdict は環境依存で動くため、AC-5（環境非依存）と表面上衝突する。
**環境差は verdict を NG 側にしか動かせない**（OK→NG 可 / **NG→OK が 1 件でもあれば FAIL**）へ精密化。
`.claude/settings.json` の有無は従来どおり**完全同一**。**TC-34**（ネットワーク有無 × git 履歴 full/shallow の 4 組合せ）+ **MUT-14**。
