## `§3-quater`（fail-closed 一般則）の要否判断 — **存続させた**

**根拠**: `legacy` が消えても、**根拠検査を要する verdict が 2 つ残る**。

| verdict | 根拠検査 | 検査不能の例 |
|---------|---------|-------------|
| `pending(defer=#N)` | 参照 issue が OPEN（**Human 発行 `defer` は残る**） | offline / `gh` 不在 / 未認証 / rate limit / timeout |
| `n/a (local)` | `targets` が全て untracked（**指摘 2 で実行時検査化**） | 非 git / tarball / `git` 不在 |

どちらも「検査できないので免除する」に倒れれば fail-open になるため、
**一般則は必要**。対象を **凍結リスト系 2 つ → `n/a (local)` 1 つ**へ差し替えて存続させた（§3-ter へ改番）。

**むしろ指摘 2 により一般則の適用範囲は広がっている** — v4 では `n/a (local)` が
一般則の外にあり、**非 git 環境で無傷に通る**穴になっていた。
